## 星驰API公益站 自动签到（v10）

站点：https://api.xingchiapi.com ｜ 每日 +300 额度，0 点（UTC+8）刷新，**不补签**

### v10 修了什么（两个真 bug）

你遇到的这两个问题，根因是同一个 —— **v9 的令牌镜像机制**：

| 现象 | v9 的根因 | v10 的做法 |
|---|---|---|
| **一个号退出，另一个号也签不到** | v9 持续把浏览器的 `refresh_token` 抄进存储，签到方的令牌**就是**浏览器那份。浏览器一退出，服务端删掉的正是你唯一那份 RT，链直接断 | 每个账号**只接管一次**：抓到 RT 后立刻自己刷新一次换出独立 RT，浏览器那份随之作废。从此签到方与浏览器**完全解耦**，你退出、换号、清缓存都不影响 |
| **两个号余额显示成一样** | v9 写的是**全局键** `xingchi_auth:captured`，每抓一次就覆盖成"最后一个账号"；解不出邮箱时还会写进"上次那个账号"的键 → A 号拿着 B 号的令牌，显示 B 的余额 | 每账号独立键 `xingchi_auth:<email>` + 独立停机标记；签到脚本加**归属硬校验**：令牌里的邮箱必须与账号一致，不符就丢弃，绝不跨账号使用 |

### 核心机制：账号独立链

```
浏览器登录 A  ──/auth/login 响应──►  接管 A：自己刷新 → 得到专属 RT_A'
                                     写入 xingchi_auth:a@x.com
                                     置 xingchi_capture_done:a@x.com = 1
                                     （浏览器那份 RT_A 立刻作废）

此后浏览器退出 A、清缓存、换登录 B ……  与 A 完全无关，A 的链照常每天签到
```

**关键点：一个账号只需要成功接管一次，之后永远不用再管它。** 就算浏览器里退出登录、换号、重装，都不影响。

### 部署（一次性，3 分钟）

#### 1. 装 CA + 开 MITM

- Egern → 工具 → 证书 → 生成新证书 → 安装并信任（设置 → 通用 → 关于 → 证书信任设置）
- Egern → 全部连接 → 右上角 `...` → 开启 **全局 MITM**

#### 2. 添加「HTTP 响应脚本」

Egern → 工具 → 脚本 → `+` → **HTTP 响应脚本**

| 项 | 值 |
|---|---|
| 名称 | `星驰Token接管` |
| 匹配 | `^https://(api\.)?xingchiapi\.com/api/v1/auth/` |
| 脚本 URL | `https://raw.githubusercontent.com/ayioyiyo/egern-scripts/main/xingchi_capture.js` |
| 需要响应体 | **必须开启** |
| 超时 | 20 |

> 也可以直接用模块：`https://raw.githubusercontent.com/ayioyiyo/egern-scripts/main/xingchi-egern.yaml`

#### 3. 添加「定时脚本」

| 项 | 值 |
|---|---|
| 名称 | `星驰API签到` |
| Cron | `5 8 * * *` |
| 脚本 URL | `https://raw.githubusercontent.com/ayioyiyo/egern-scripts/main/xingchi_checkin.js` |
| 超时 | 60 |
| 环境变量 | **不用填**，纯靠接管 |

#### 4. ⭐ 逐个登录一次（双账号的关键）

**同一个浏览器同一时间只能登录一个号**（`localStorage` 按域名共享，后登录会覆盖前一个）。
所以请按这个顺序操作，**每个号各做一次**：

```
① 打开 https://api.xingchiapi.com ，登录【账号 A】（手动点一下人机验证）
② 收到通知「星驰Token已接管 → a@x.com」= A 已完成，之后不用再管 A
③ 退出登录 / 清空站点数据 / 换无痕窗口
④ 登录【账号 B】，同样等「已接管 → b@x.com」通知
⑤ 完成。以后两个号各自独立签到，互不影响
```

> 已接管的账号，再登录它不会重复接管（脚本该账号第一行就放行，零请求）。

### 验证

长按定时脚本 → **立即运行**，通知里每个账号会各自显示**自己的**余额：

```
a@x.com：今日已签到（今日 +300，累计 2 天 / 600），余额 $6.00
b@x.com：签到成功 +300（累计 1 天 / 300），余额 $13.00
```

**两个余额不一样**才说明账号隔离生效了。

### 升级到 v10 后务必清一次旧数据

v9 留下的污染数据会被 v10 自动丢弃（归属校验），但为了干净，建议先清掉：

Egern → 工具 → 脚本 → 找到脚本 → **清空脚本存储**（或删除下列键）：

- `xingchi_auth:captured`（v9 的全局键，污染源）
- `xingchi_capture_done`（v9 的全局停机标记）
- 任何 `xingchi_auth:<邮箱>` 里**邮箱与键名不符**的条目

清完按上面第 4 步重新登录每个账号一次即可。

### 常见问题

**Q：升级后某个号还是签不到？**
看通知里的原因：
- 「存储中的令牌属于其他账号，已丢弃」→ 正常，v10 在清理 v9 污染。登录该号一次即可
- 「本地 refresh_token 已失效」→ 该号需要重新登录一次
- 「接管验证失败」→ 网络问题，重新登录一次

**Q：为什么不能两个号同时保持登录？**
站点前端把登录态放在 `localStorage`（按域名共享），一个域名只能存一份。这是站点设计，脚本无法改变。但**接管之后就不需要保持登录了**，这正是接管机制的价值。

**Q：多久需要重新登录一次？**
正常情况下**永远不用**。服务端 RT 没有固定有效期（靠每次轮换续命），脚本每天签到都会自动轮换。只有当你在浏览器里主动「退出登录」并且该号**尚未接管**时，才需要重新登录。

**Q：想彻底重置某个号？**
删掉 `xingchi_auth:<该号邮箱>` 和 `xingchi_capture_done:<该号邮箱>` 两个键，重新登录该号一次。

### 手动指定账号（不靠抓取，备用）

```json
XINGCHI_ACCOUNTS = [{"name":"主号","email":"a@x.com","refresh_token":"rt_xxx"}]
```

注意：`refresh_token` 必须真的是该 `email` 的，否则会被 v10 的归属校验丢弃（这是有意的保护）。

## 文件说明

| 文件 | 类型 | 作用 |
|---|---|---|
| `xingchi_capture.js` | http_response | 登录时接管该账号令牌（每号一次），与浏览器解耦 |
| `xingchi_checkin.js` | schedule | 每天读取各账号独立令牌签到，带归属校验 |
| `xingchi-egern.yaml` | 模块 | 一键导入上述配置 |
